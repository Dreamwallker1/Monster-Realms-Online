---
name: Mythora Zod rarity enum
description: The rarity field in lib/api-zod must match the actual DB values used by myths; mismatch causes 500 on every encounter.
---

**Rule:** The `rarity` Zod enum in `lib/api-zod/src/generated/api.ts` must always match the values stored in the `monster_species.rarity` column.

Current correct enum: `['C', 'B', 'A', 'S']` (quality tiers, not old verbose names).

**Why:** `ExploreTileResponse.parse()` validates the encounter species including its rarity field. If the DB stores `"C"` but the Zod enum only accepts `"Common"`, the server throws a ZodError 500 on EVERY triggered encounter — silently eating all encounters. This was the root cause of "myths never appearing" despite the encounter probability (30%) being correct and region monsterSpeciesIds being populated.

**How to apply:**
- After any change to the rarity values stored in myth data, update `lib/api-zod/src/generated/api.ts` with a global sed replace.
- The file is generated by orval but we edit it directly — do NOT regenerate without also updating the values.
- After editing, restart the API server (esbuild bundles from source, picks up changes).
- The dist/ folder only has `.d.ts` files; both Vite and esbuild use the TypeScript source directly.
- Also update: `selectWildMonster` rarityWeight keys in `gameEngine.ts`, `RARITY_COLORS` in `element-colors.ts`, and any filter dropdowns in the UI.

**Encounter rate:** 30% on grass tiles (tileType=0), hardcoded in exploration.ts. Actual observed rate ≈ 43% per step in verdant-meadows because the walk stays on grass.
